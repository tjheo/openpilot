# SVX 실시간 RPM (svx_live) — 읽기 전용, 선택 사항, 기본 꺼짐

콤마가 엔진 RPM(EMS11 0x316)을 **읽기만** 해서, 같은 Wi-Fi(또는 테일넷)에 있는 폰의 SVX 가상배기음 앱(0.3.0 이상)에 보냅니다.
폰이 TCP로 콤마에 접속해 짧은 인사(핸드셰이크)를 하면, 같은 연결로 RPM이 계속 옵니다. **키, 명령어, 설정 파일이 없습니다.**

## 매일 쓰는 방법
1. 콤마 화면 **설정 → 토글**에서 이 기능을 켭니다. 한 번 켜 두면 계속 유지됩니다.
   * C4 화면(mici): **"svx live rpm to phone"** (C4 토글 화면의 다른 항목들처럼 영어 소문자로만 표시됩니다)
   * C3/C3X 큰 화면: **"SVX 실시간 RPM 폰 전송"** (한국어 설정일 때. 영어 설정이면 "SVX Live RPM to Phone")
2. 시동을 켭니다. 콤마가 주행 상태(onroad)가 되면 TCP 47816 포트에서 기다립니다.
   * 차가 움직일 필요는 없습니다. 정차 중이라도 시동이 켜져 있으면 됩니다.
3. 폰 앱에서 콤마 IP(처음 한 번 저장)를 확인하고 **[실시간 (콤마)]**를 누릅니다.

앱 화면에 지금 상태가 자동으로 표시됩니다: 연결 중 / 콤마 응답 없음 / 차량 인식 대기 / 지원하지 않는 차량 / EMS11 프레임 없음 / RPM 오래됨 / 거부됨 / 시간 초과 / 정상.
소리는 "정상"일 때만 납니다. 다른 상태가 되면 앱은 목표 음량을 바로 0으로 내립니다. 실제로 소리가 사라지기까지는 페이드아웃(최대 0.4초)과 오디오·전송 버퍼 지연이 더해집니다. 이 시간은 실차에서 측정하지 않았습니다.

## 동작 규칙
* **언제 실행되나:** 토글이 켜져 있고(`SvxLiveEnabled`), 장치가 onroad(`deviceState.started`)일 때만 manager가 `svx_lived`를 실행합니다.
  * 시동이 꺼진 상태(offroad)나 토글이 꺼진 상태에서는 실행되지 않습니다. 포트도 열리지 않고 CAN도 구독하지 않습니다.
  * manager는 꺼져 있을 때도 모듈을 미리 import합니다. 그래서 import만으로는 소켓, Params, 구독 같은 어떤 동작도 일어나지 않게 만들었습니다 (테스트로 확인).
* **끄기:** 토글을 끄면 약 0.5초 안에 폰 연결에 종료 신호(`BYE STOPPING`)를 보내고 프로그램이 끝납니다. manager도 1초 안에 정지시킵니다.
* **포트:** 파라미터 `SvxLivePort`(기본 47816, 1024~65535)입니다.
  * 평소에는 바꿀 필요가 없습니다. 화면에는 포트 편집 칸이 없습니다.
  * 다른 포트가 꼭 필요할 때만 이 파라미터를 직접 씁니다 (선택 사항).
  * 잘못된 값이면 포트를 열지 않습니다. 바꾼 뒤에는 토글을 껐다 켜야 적용됩니다.
* **누가 접속할 수 있나:** 사설 LAN(10/8, 172.16/12, 192.168/16)과 테일넷(100.64/10) 주소만 됩니다. 그 밖의 주소는 1바이트도 보내지 않고 바로 끊습니다.
  * **키가 없으므로 인증이 아닙니다.** 같은 네트워크의 누구나 RPM을 읽을 수 있습니다.
  * 폰이 보낼 수 있는 것은 인사(HELLO)와 연결 확인(PING)뿐입니다. 명령·설정·진단·쉘 기능은 없습니다. 폰이 보내는 어떤 내용으로도 차량, CAN, 파라미터, 파일을 바꿀 수 없습니다.
* **제한:** 동시에 폰 2대까지 받습니다. 같은 폰이 다시 접속하면 예전 연결을 대신합니다.
  * 접속 시도, 메시지 수, 버퍼 크기, 시간 초과에 모두 상한이 있습니다.
  * 50Hz 고정 주기로 동작하고 우선순위는 nice 19입니다.
  * 받는 쪽이 느리면 새 RPM을 쌓아 두지 않고 버립니다. 보내다 만 프레임 하나와 짧은 응답만 작은 상한 안에서 남습니다.
* **RPM 원본:** `can` 서비스를 **구독만** 하고 `CarParams` 파라미터를 **읽기만** 합니다.
  * 차량이 지원 차량으로 확인된 뒤에만 `can`을 구독합니다.
  * 다음은 전혀 하지 않습니다: 퍼블리셔 생성, sendcan, Panda/USB/socketcan 접근, 진단(OBD/UDS) 요청, 파라미터 쓰기.
  * 조향·제동·가속·모델 코드는 바꾸지 않았습니다.
  * 실제 RPM을 그대로 보냅니다. "4,000 rpm에서 최고 소리" 같은 대응은 앱 안에서만 합니다.

## 지원 범위 (이 밖은 소리 없음으로 거부)
* 차량 선택: `KIA_SELTOS`(hyundai), **CAN-FD 아님**. CAN **bus 0**의 EMS11(0x316)만 씁니다.
  * 레이아웃은 이 저장소 `hyundai_kia_generic.dbc`의 `EMS11` `N`입니다: 시작 비트 16, 16비트, 리틀엔디언, 0.25 rpm 단위 (테스트로 DBC와 대조).
* 다른 차, CAN-FD 셀토스, CarParams 없음은 각각 "지원하지 않는 차량" 또는 "차량 인식 대기"로 표시되고, 유효 RPM을 보내지 않습니다.
* CarParams는 2초마다 다시 읽습니다. 바뀌거나 사라지면 모든 데이터를 버리고 연결을 끊습니다 (`BYE CAR_CHANGED`). 폰은 새로 접속합니다.
  * CarParams는 onroad 전환과 manager 시작 때 지워지고 card가 새로 씁니다. 이 프로그램은 onroad일 때만 돌기 때문에 지난 주행의 값을 쓰지 않습니다.
* `carState.engineRpm`은 쓰지 않습니다. 현대/기아 carstate가 이 값을 채우지 않기 때문입니다.
* **실제 차량에서 EMS11이 bus 0에 나오는지는 확인되지 않았습니다.** 나오지 않으면 앱에 "EMS11 RPM 프레임 없음"이 표시됩니다.

## RPM을 쓰지 않는 경우 (앱은 소리 없음)
* 다음 프레임은 쓰지 않습니다:
  * 300ms보다 오래된 프레임. 나이는 `logMonoTime` 기준이며, 큐에서 꺼낸 시각이 아닙니다. 밀린 큐를 늦게 읽어도 신선해지지 않습니다.
  * 미래 시각, 순서가 바뀐 프레임, 중복 프레임
  * 길이가 8바이트가 아닌 프레임
  * 다른 버스나 TX 에코에서 온 프레임
* 다음 경우에는 그보다 오래된 정상 데이터로 돌아가지 않고 즉시 "RPM 무효"를 보냅니다:
  * 가장 최근의 `can` 이벤트가 `valid=false`이거나 해석할 수 없을 때
  * 가장 최근 EMS11 프레임이 거부되었을 때
* RPM 0은 엔진 정지로, F_N_ENG 고장 비트·0xFFFF·9,000rpm 초과는 무효로 보냅니다.
* 앱 쪽 판정 (앱 0.3.0, 자세한 내용은 `PROTOCOL.md`):
  * 무효 상태가 오면 목표 음량이 바로 0이 됩니다 (그 뒤 페이드와 버퍼 지연).
  * 다시 소리를 내려면 새 프레임이 들어와야 합니다.
  * 앱이 보낸 연결 확인(PING)에 대한 최근 응답 뒤에 받은 데이터만 씁니다. 네트워크가 막혔다가 한꺼번에 들어온 옛 데이터는 신선하게 보이지 않습니다.

## 처음 설치·업데이트 (실제 배포와 구분)
이 저장소 작업에서 차량이나 콤마에 설치하거나 실행한 적은 **없습니다.** 아래는 안내입니다.
* 이 기능은 포크 브랜치에 들어간 코드입니다. 콤마가 이 코드를 실행하려면 이 기능이 들어간 버전으로 **업데이트한 뒤 재시작(재부팅)**해야 합니다.
  * `git pull`만 하고 재시작하지 않으면 이미 실행 중인 manager·UI가 계속 옛 코드로 돕니다. 토글도 보이지 않습니다.
* 새 파라미터(`SvxLiveEnabled`, `SvxLivePort`)는 `common/params_keys.h`에 있어서 params 모듈을 다시 빌드해야 인식됩니다.
  * 이 포크의 정상 업데이트·빌드 과정을 거치면 됩니다.
  * 빌드가 아직 반영되지 않았을 때는 토글이 화면에 나타나지 않고, manager도 이 프로그램을 실행하지 않습니다. 오류로 멈추지는 않도록 처리했습니다.
* 폰 앱도 **0.3.0 이상**이어야 합니다. 0.2.2 이하 앱(UDP)과는 호환되지 않습니다.

## 끄기 / 되돌리기
* 끄기: 토글을 끕니다. 기본값이 꺼짐이므로, 켜지 않은 장치에서는 아무것도 실행되지 않습니다.
* 되돌리기: 이 기능이 없는 이전 버전으로 되돌리면 됩니다. 남은 파라미터 값은 아무 효과가 없습니다.

## 예전 수동 송신기(tools/svx_rpm)
* 키를 만들고 SSH로 실행하던 수동 UDP 송신기(`tools/svx_rpm`, PR #1)는 이 기능으로 대체되어 제거되었습니다.
* 재사용한 부분: EMS11 해석, 차량 프로파일, 신선도 판정, `can` 구독 코드, 그리고 해당 테스트들입니다. 모두 이 폴더로 옮겼습니다.
* 0.2.2 이하 앱이 쓰던 SVX1 UDP 형식은 0.3.0 앱이 더 이상 받지 않습니다.

## 한계
* 실제 콤마·차량·폰에서 실행해 보지 않았습니다 (`VERIFICATION.md`). EMS11의 존재, 버스, 주기, 지연은 실차 확인이 필요합니다.
* 이 서버에는 msgq·raylib가 빌드되어 있지 않습니다. 그래서 다음은 실행하지 못했습니다:
  * 실제 `can` 소켓 구독
  * 실제 화면 그리기
* 대신 다음 방식으로 확인했습니다:
  * 실제 cereal 스키마로 만든 이벤트를 넣는 테스트
  * 위젯을 대체한 설정 화면 테스트
  * 실제 TCP 소켓으로 Python 서버와 앱(JVM) 클라이언트를 연결한 테스트
* `params_keys.h`는 g++로 따로 컴파일해 두 키만 확인했습니다. 전체 scons 빌드는 하지 않았습니다.

## 출처와 라이선스
* EMS11 디코더, 프로파일, 신선도 로직, `ems11_frames.json`은 PR #1(`tools/svx_rpm`)에서 옮겨 왔습니다.
  * 그 코드는 저장소 소유자 본인의 SVX 프로젝트에서 가져와, 소유자 승인에 따라 이 저장소의 라이선스(MIT, 저장소 루트 `LICENSE`)로 공개되었습니다.
  * 원래 프로젝트가 MIT였다는 뜻은 아닙니다.
* 새 TCP 프로토콜과 서버는 이 변경에서 새로 작성했습니다 (Python 표준 라이브러리만 사용).
* EMS11 신호 정의는 opendbc(MIT, `opendbc_repo/LICENSE`)의 `hyundai_kia_generic.dbc`를 참조했습니다. DBC 파일은 복사하지 않았습니다.
* 제3자 코드, 음원, 바이너리, 키는 포함되어 있지 않습니다.
